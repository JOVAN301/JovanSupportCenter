# Jovan Support Center — v5 deployment

## What v5 adds
- Production Dockerfile for the Node/Express backend.
- Render Blueprint (`render.yaml`) with a health check and persistent SQLite disk.
- Database is stored at `/var/data/jovan-support.db` so it survives redeploys when the persistent disk is attached.
- `JWT_SECRET` is generated by the deployment platform rather than stored in source code.

## Deploy
1. Create a Git repository and upload the project contents.
2. In Render, create a Blueprint from that repository.
3. Review the generated web service and persistent disk before creating it.
4. After deployment, open the generated service URL and check `/health`.
5. The API base URL used by the Android app should be the service URL, without a trailing slash.
6. Set a strong admin email/password as environment variables and run the admin seed command once, or create an admin through a controlled database operation.

## Important production notes
- This version uses SQLite on a persistent disk. It is suitable for an initial single-instance deployment, not horizontal scaling.
- For larger production usage, migrate the database to managed PostgreSQL before enabling multiple backend instances.
- Restrict CORS to the actual Android/web origins once those are known.
- Keep payment credentials and API secrets out of source code.
- Do not treat a client-reported payment as successful; verify payment-provider webhooks server-side.
